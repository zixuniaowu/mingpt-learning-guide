核心思想（贯穿全书）：
GPT 的全部工作就是：给定一串整数（token IDs）→ 预测序列中每个位置「下一个最可能出现的整数」的概率分布。

仅仅两年后，OpenAI 发布了 GPT-2，用一个纯粹的“猜下一个词”的模型，在几乎没有任务特定训练的情况下，展现出了惊人的能力：写文章、翻译、问答、编程…… 人们开始意识到：规模 + 简单目标 + 海量数据，可能就是通往通用智能的一条路径。

2020 年，GPT-3 进一步证明了这一点。2022 年底，ChatGPT 的横空出世，让全世界都感受到了这种技术的力量。

minGPT 就是 Andrej Karpathy 为了让任何人（尤其是学生和研究者）都能真正理解这个核心而写的极简实现。它只有几百行代码，却完整复现了 GPT 的所有关键思想。

1. 定义 Dataset —— 从第一性原理理解“下一个词预测”的数据形式

训练的起点是数据。模型不会“魔法般”学会东西，它只能通过大量例子知道：给定前面的 token，正确的下一个 token 应该是什么。

语言建模用的是自监督学习：不需要人工标注答案，因为一句话本身就能产生答案。只要把同一串 token 向右错开一格，就得到了训练目标。

核心思想：输入和答案只差一格

假设有一串数字序列：[10, 20, 30, 40, 50, 60]。GPT 要学的不是“记住这串数字”，而是：

看到 10，预测 20；看到 10,20，预测 30；看到 10,20,30，预测 40……

用人类直觉写出来，就是很多个小问题：

例子编号模型看到的 x（输入）正确答案 y（目标）
1[10]20
2[10, 20]30
3[10, 20, 30]40
.........

但代码不会把这些小问题一条条单独喂给模型。为了并行训练，Dataset 会一次返回两条等长序列：

  • x：模型看到的 token 序列
  • y：正确答案序列，等于原序列向左移动一格，也就是“每个位置的下一个 token”

最简单的例子（block_size = 5）

如果 block_size = 5，Dataset 会先取 block_size + 1 个 token，也就是 6 个 token：

chunk = [10, 20, 30, 40, 50, 60]
x = chunk[:-1]  # [10, 20, 30, 40, 50]
y = chunk[1:]   # [20, 30, 40, 50, 60]

于是一次训练样本其实长这样：

位置01234
x（输入）1020304050
y（目标）2030405060

这张表的意思是：

  • 在位置 0：看到 10，要预测 20
  • 在位置 1：看到 10,20，要预测 30
  • 在位置 2：看到 10,20,30，要预测 40
  • 在位置 3：看到 10,20,30,40，要预测 50
  • 在位置 4：看到 10,20,30,40,50，要预测 60

注意：模型输入的 x 里没有 60，但 y 里有 60，因为 60 正是最后一个位置要预测的答案。这就是“下一个 token 预测”的本质。

一句话记住：Dataset 不是给模型“问题和答案两段文本”，而是把同一段文本错开一格：x = 前 N 个 token，y = 后 N 个 token。模型在每个位置都猜下一个 token，loss 负责告诉它猜得对不对。

为什么 y 里会出现 -1？—— adder 项目的实际用法（深入拆解）

上面那个简单例子是“纯生成”任务。但很多真实任务是“先看问题，再给出答案”。

以 projects/adder 为例，这是 Karpathy 设计的一个极简实验：让 GPT 从零学会做 n 位数加法。

编码方式（以 2 位数为例）

问题 85 + 50 = 135 被编码成字符串 "8550531"（长度 7）：

  • 前 2 位：被加数 85 → 8,5
  • 中间 2 位：加数 50 → 5,0
  • 最后 3 位：结果 135 反向编码 → 5,3,1（个位、十位、百位）

注意：真实代码里没有 +，也没有 = 这个分隔符。模型只看到一串数字：8 5 5 0 5 3 1。

构造 Dataset 时：

  • render = [8,5,5,0,5,3,1]（完整字符串）
  • x = [8,5,5,0,5,3]（去掉最后一位，因为没有下一个位置再用它预测）
  • y = [5,5,0,5,3,1]（render 向左错开一格，也就是每个位置的“下一个 token”）

但我们只想让模型在“输出答案”的位置上学习，前面的“读题”位置不应该产生 loss。

因此代码把 y 的前 3 个位置设成特殊值 -1：

位置012345
x855053
模型此处要预测的原始 y550531
屏蔽后的 y-1-1-1531

为什么一定要反向编码结果？

反向编码和 -1 屏蔽不是一回事：

  • -1 屏蔽：决定哪些位置参与 loss。它的作用是“只训练答案部分”。
  • 反向编码：决定答案数字的生成顺序。它的作用是“让模型按加法算法的自然顺序输出答案”。

人做竖式加法时，是从右往左算的：先个位，再十位，再百位，因为进位是从低位传到高位的。

对 85 + 50 = 135 来说：

  • 个位：5 + 0 = 5，所以第一个应该输出 5
  • 十位：8 + 5 = 13，所以第二个输出 3，并产生进位 1
  • 百位：输出进位 1

所以答案按计算顺序是 5,3,1。如果正向输出 1,3,5，模型一上来就必须预测最高位 1；但这个 1 来自后面低位计算产生的进位。对一个只能从左到右生成的 GPT 来说，这会让任务难很多。

一句话：-1 是为了“在哪些位置学习”；反向编码是为了“按什么顺序学习答案”。反向后，第一个有效 loss 位置就是个位答案 5，正好对应加法最先能算出来的那一位。

图：Adder 数据构造与梯度屏蔽示意图（看图说话版）

看这张图就能明白核心：

  • 上方整行是模型真正“读到”的 x。
  • 下方只有后面三个绿色格子是有效的 y（模型真正需要预测的答案部分）。
  • 前面三个红色 -1 的位置，损失为 0，梯度为 0 —— 模型在这里无论猜什么都不会被惩罚。
  • 这就强迫模型把学习能力集中在“如何从问题计算出答案”上，而不是去记忆“问题长什么样”。

在训练的一步中到底发生了什么？（更细的拆解）

当 Trainer 取到一个 adder 的 batch 时，模型会：

  1. 看到 x（完整问题 + 已经出现的反向答案前缀）。
  2. 在每一个位置输出对“下一个 token”的预测（logits）。
  3. 只在 y 不是 -1 的位置计算交叉熵损失（即只在答案的 3 个位置计算）。
  4. 反向传播时，梯度只从那 3 个位置回传，更新模型参数，让它下次在类似问题上能更准地预测答案的每一位。

经过成千上万这样的例子后，模型内部的“旋钮”就被调成了一个能做加法的加法器，而不是一个死记硬背的查找表。

如果我们把结果正向写会怎样？（对比实验思维）

假如我们把结果正向写（135 → 1,3,5），模型在预测第一个数字（1）时，还不知道个位是否有进位。

它必须同时学会“预测 + 记住进位”两个事情，学习难度大幅上升，收敛会慢很多，甚至学不会。

反向写把“进位”这个信息自然地放在了预测顺序的最前面，大大降低了学习难度。这就是好的数据构造能带来的巨大帮助。

与标准语言建模的对比

在普通的 chargpt（字符级语言模型）中，我们通常对整个序列都计算损失（除了最后一个位置）。

因为语言建模的“问题”和“答案”是连续的，没有明显的“读题”和“答题”分离。

而在 adder 这种“算法性”任务中，我们必须人为制造这种分离，否则模型学到的就不是算法，而是记忆。

这个思想在今天的大模型时代依然非常重要：我们通过精心构造的指令数据 + 只监督回答部分的损失，来让模型学会“遵循指令”而不是“复述指令”。

第一部分：语言建模与表示基础（最重要的一章）

我们从零开始，通过一个具体的例子，把「文本 → 数字 → 模型思考 → 预测下一个词」讲清楚。

1. 语言建模到底在干什么？——「永远在猜下一个字」的游戏

你小时候有没有玩过「接龙」游戏？老师说「今天天气很好，」你马上接「我」或者「适合」或者「出去玩」。

GPT 做的就是这件事，而且它要做到极致：给定前面所有的字，它要给「下一个最可能出现的字」打分。

它不是在「理解意思」，而是在海量文本里学到了统计规律：「在『我喜欢』后面，『猫』出现的次数比『飞机』多得多」。

用一个具体例子走一遍

我们用一句话：「我 喜欢 猫」（中文为了方便先用英文 "I like cats" 演示，因为 GPT-2 用英文 BPE）

模型的任务是：

  • 看到「I」 → 猜下一个可能是 like / am / hate ...
  • 看到「I like」 → 猜下一个可能是 cats / dogs / pizza ...
  • 看到「I like cats」 → 结束或猜句号

训练时，我们把正确答案告诉它（监督学习），让它越来越准。

2. 语言建模与学习的第一性原理

到目前为止，我们只说了“模型的任务是猜下一个词”。但它是怎么从“完全不会猜”变成“会猜”的呢？

这涉及到 AI 最核心的三个基本机制。我们从第一性原理开始讲。

任何学习系统只有三件事

不管是人学习打篮球，还是神经网络学习猜词，本质上都只有三步循环：

  1. 做一个猜测（前向传播 Forward）
  2. 衡量这个猜测有多离谱（计算损失 Loss）
  3. 根据离谱程度，稍微改一改内部的“旋钮”，让下一次猜得更好（梯度下降 + 参数更新）

模型内部有成千上万个“旋钮”（就是那些权重参数）。训练就是反复拧这些旋钮，让它在同样的问题上犯更少的错误。

损失函数：错误评分器

损失函数（Loss Function）就是“错误评分器”。它的唯一工作是：给当前猜测打一个分数，分数越低越好。

对于“猜下一个词”这种任务，我们用的是交叉熵损失（Cross Entropy Loss）。

它的直觉非常简单：

模型会对每个可能的词给出一个概率（加起来等于 1）。如果它给“正确答案”的概率很高，损失就很小；如果给正确答案的概率很低（它很“惊讶”），损失就很大。

下面是一个极简的例子（假设只有 3 个可能的词 A、B、C，正确答案是 B）：

模型给出的概率对正确答案 B 的信心损失大小（直觉）
[0.1, 0.8, 0.1]很高（80% 认为 B）很小 ✓
[0.3, 0.4, 0.3]中等中等
[0.6, 0.2, 0.2]很低（只给 B 20%）很大 ✗

在 minGPT 的代码里，这一行就是计算损失：

loss = F.cross_entropy(
    logits.view(-1, vocab_size),   # 模型的原始打分
    targets.view(-1),              # 正确答案的 token ID
    ignore_index=-1
)

它内部会先把 logits 变成概率（softmax），然后计算“正确答案的概率越低，损失越高”。

梯度下降：怎么知道该怎么改旋钮？

现在我们知道当前有多错（损失值）。问题来了：模型里有几十万甚至上亿个旋钮，到底该拧哪一个、往哪个方向拧？

答案是梯度（Gradient）。

你可以把损失想象成一座山（山越高 = 错误越大）。我们站在山坡上，想走到山谷（损失 = 0）。

梯度就是“在你现在站的位置，如果把某个旋钮往左拧一点，山是变高还是变低？变高多少？”

梯度下降的做法就是：每次都朝让山变低（损失下降）最快的方向，拧一小步。

这一小步的大小由学习率（learning_rate）控制。拧得太猛容易冲过山谷，拧得太小则要走很久。

经典可视化：损失地形图（Loss Landscape）

网上最经典的梯度下降示意图，就是把损失画成一个“碗”或“山谷”的三维曲面（或二维等高线图），一个小球（代表当前参数）在上面滚动。

下面是一个可交互的简化动图（2D 版本，便于理解核心思想）。你可以调整学习率，看看小球怎么“滚下山”：

红色曲线 = 损失函数（简单二次函数 f(x)=x²）。蓝色点 = 当前参数位置。绿色箭头 = 梯度方向（指向损失增加最快的方向）。每次点击“单步”或运行，点会沿负梯度方向移动。
小 LR：慢慢滚下山（稳定但慢）。大 LR：可能冲过谷底震荡。加动量后路径更平滑，像小球有惯性。

看这张动图就能直观理解梯度下降：

  • 红色曲线 = 损失函数（抛物线，越往中间越低 = 损失越小）。这就是模型当前“有多错”。
  • 红色小球 = 你当前的参数位置（现实中是几十亿维，这里简化成 1D）。
  • 绿色箭头 = 梯度方向（损失在这个点上升最快的方向）。我们永远朝相反方向（下山）走。
  • 拖动左边的“学习率”滑块，立刻能看到小球的行为变化：太小 = 慢慢爬；太大 = 冲过谷底乱晃。
  • 打开右边的“动量”，小球会带着惯性，路径明显更稳、更快（这就是为什么现代优化器要加 momentum）。

在真实 GPT 训练中，损失地形是几亿维的“超级复杂山脉”。AdamW 就是在不同维度上自适应调“步长”和“惯性”，让小球能更快更稳地滚到谷底。

这就是为什么我们说“梯度下降 = 让参数往损失下降最快的方向小步移动”。反向传播（loss.backward()）负责算出这个“最快下降方向”（梯度），optimizer.step() 负责真正移动参数。

反向传播：自动算梯度

手动算每个旋钮的梯度几乎不可能。幸运的是，PyTorch 提供了 loss.backward()。

它使用“链式法则”（Chain Rule）从后往前自动计算：这个错误到底要怪谁？怪前面哪一层？怪哪个参数？

这个从输出错误一路“倒推责任”的过程，就叫反向传播（Backpropagation）。

想象一个非常简单的神经网络只有两层：

输入 → 隐藏层（带权重 W1） → 输出层（带权重 W2） → 损失

当我们得到损失后，反向传播会先问：“输出层的错误主要怪谁？”（怪 W2 比较多）。

然后把这个“错误信号”传给隐藏层，再问：“隐藏层的错误主要怪谁？”（怪 W1）。

最后把所有错误信号变成每个权重的梯度。

图：反向传播“倒推责任”示意图

看这张图：损失从最右边产生后，错误信号像“倒推责任”一样一级一级往回传。每一层都要承担一部分责任，最终变成对每个权重的梯度。

这就是为什么我们说“梯度是误差对参数的偏导数”——它精确量化了“如果我把这个参数改动一点点，损失会变多少”。

在实际训练循环里是怎么运作的？

看一下 Trainer 里的核心循环（我们后面会有完整的小实验让你跑）：

logits, loss = model(x, y)            # 1. 前向：做猜测 + 计算有多错
model.zero_grad(set_to_none=True)
loss.backward()                       # 2. 反向：算出每个旋钮该怎么拧
optimizer.step()                      # 3. 更新：真正拧这些旋钮

图：完整训练循环的可视化

重复这个循环几千次，模型内部的旋钮就会慢慢调整到让它在训练数据上猜得越来越准的位置。

第一性原理总结：
训练 = 不断重复「猜测 → 打分（损失）→ 找下降最快的方向（梯度）→ 拧一小步（更新参数）」。
损失函数告诉你“现在有多错”，梯度下降告诉你“该往哪里改”，反向传播让这个过程能自动进行。

现在你已经理解了“学习”最本质的三个零件。后面当我们看到具体代码时，会不断回到这三个概念。

3. 序列建模的历史演进：从 RNN 到 Transformer

要真正理解 GPT 为什么选择 Transformer，我们必须先了解在它之前，人们是如何处理序列数据的，以及那些方法遇到了什么根本性问题。

循环神经网络（RNN）的时代

在深度学习早期，处理文本最常用的模型是循环神经网络（Recurrent Neural Network）。

核心思想：用同一个“细胞”按顺序处理序列的每一个元素，同时维护一个“隐藏状态”（hidden state），这个状态携带了前面所有信息的摘要。

类比：你一边读一本书，一边在脑子里不断更新“目前读到哪了、故事讲到什么程度”这个心理状态。

RNN 的数学形式非常简单：

hₜ = tanh(Wₕₕ · hₜ₋₁ + Wₓₕ · xₜ + b)

问题很快就暴露了：

  • 梯度消失/爆炸：当序列很长时，反向传播要穿过很多时间步。梯度要么越来越小（前面的信息完全学不到），要么越来越大（训练直接崩溃）。
  • 无法并行：必须严格按时间顺序计算第 t 步依赖第 t-1 步。在 GPU 上这非常低效。
  • 长距离依赖困难：模型很难记住 50 步之前的信息。

LSTM 和 GRU 的改进

为了解决梯度消失问题，研究者提出了 LSTM（Long Short-Term Memory）和后来的 GRU。

它们引入了“门控”机制（遗忘门、输入门、输出门），让模型可以选择性地记住或忘记信息。

这在当时是巨大的进步，很多语音识别、机器翻译系统都用 LSTM 取得了当时最好的结果。

但根本问题依然存在：

  • 仍然是顺序计算，无法充分利用现代硬件的并行能力。
  • 虽然缓解了梯度消失，但长距离依赖依然脆弱。
  • 模型复杂度高，训练和推理都很慢。

Seq2Seq + Attention 的过渡

2014 年，Seq2Seq（序列到序列）模型提出：用一个 RNN 把输入编码成一个固定向量，再用另一个 RNN 解码生成输出。

这在机器翻译上非常成功。但很快人们发现：把整个输入压缩成一个向量是瓶颈。

于是，Bahdanau Attention（2014）和 Luong Attention 出现了。

关键突破：解码时不再只看一个固定向量，而是可以“动态关注”输入序列的不同部分。

这时注意力已经不是主角，它只是 RNN 的一个辅助模块。

2017：Attention Is All You Need

Google 的这篇论文做了最彻底的决定：扔掉循环结构，只用注意力。

他们提出了 Self-Attention（自注意力）：序列中的每一个位置都可以直接和其他所有位置计算相关性，而不需要按顺序传递信息。

这带来了革命性的优势：

维度RNN/LSTMTransformer (Self-Attention)
并行性极差（必须顺序）极好（所有位置可同时计算）
长距离依赖困难一步到位（任何距离都是 O(1)）
计算复杂度（序列长度 n）O(n)O(n²)（但常数小，实际更快）
可解释性较差注意力权重直接可视化

Transformer 一经提出，就在机器翻译任务上大幅超越了之前的 SOTA，而且训练速度快了一个数量级。

这为后续 GPT、BERT、T5 等所有现代大模型奠定了基础。

为什么 GPT 选择了纯 Decoder？

原始 Transformer 有 Encoder 和 Decoder 两部分。不同的架构选择，本质上是“注意力能看到多远”的区别。

用一句话“我 喜欢 猫”来看三种架构分别怎么处理：

图 3.3：三种架构的注意力可见范围

用具体例子理解区别：假设模型在读“我喜欢猫”，停在“猫”这个位置：

模型“猫”能看到什么？为什么？
BERT
(Encoder)		 我, 喜欢, 猫 （全部） 双向注意力没有遮罩，左右两边都能看。“猫”的表示同时包含了“我”和“喜欢”的完整信息。适合做分类、情感分析等理解任务。
GPT
(Decoder)		 我, 喜欢 （只看左边，不能看右边） 因果遮罩把右边的 future token 遮住了。“猫”的位置只知道左边出现过“我喜欢”。因为生成时你根本还没有右边的 token——这是一个“从前往后”的生成过程。
T5 Encoder 看全部 + Decoder 因果生成 先让 Encoder 双向看完输入（理解整句话），再让 Decoder 因果生成输出（翻译/摘要等）。相当于先理解，再创作。
核心理解：所谓“双向”就是注意力不加限制，每个词都能看到整个句子的所有其他词。所谓“因果”就是加了一个遮罩（mask），强迫每个位置只能看自己及左边的 token。

这完全由模型结构一层代码的区别决定——在注意力计算中是否应用了 causal mask。

事实证明，对于“下一个词预测”这个极度通用的预训练目标，纯 Decoder + 自回归是最简单也最有效的：你用“预测下一个词”来训练它，再用完全同样的“预测下一个词”方式来生成，训练和推理的目标天然对齐。BERT 的双向注意力虽然能看更多上下文，但它的训练方式（填空）和推理方式（理解）不完全一致，作为生成模型也不够自然。

与视觉 Transformer (ViT) 的对比

Transformer 不仅统治了 NLP，也进入了计算机视觉。ViT (Vision Transformer) 把图像切成 patch，当作序列来处理。

关键区别：

  • 视觉中没有天然的“因果”顺序，所以 ViT 用双向注意力 + 位置编码。
  • 但在视频生成或自回归图像生成任务中，人们又开始用类似 GPT 的因果版本 (如 ImageGPT)。
  • 这说明注意力机制非常通用，具体是 causal 还是 bidirectional，主要由任务的“生成 vs 理解”性质决定。
历史给我们的启示：很多看似复杂的进步，其实是把“归纳偏置”去掉、让模型自己从数据中学习的结果。RNN 有很强的时序归纳偏置，Transformer 几乎没有，它把一切都交给注意力去发现。视觉和语言的成功进一步证明了这一点。

4. Tokenization 与表示（BPE 实现）

电脑只认识 0 和 1。文字必须先翻译成一串整数。

最简单的办法是「每个字母一个编号」——但这样序列太长，模型要背很多「拼写规则」。

GPT-2 用的是叫 BPE（字节对编码） 的聪明方法：

  • 先用空格和标点把句子「粗切」成小块。
  • 把每个字节映射成「看起来好看的符号」（空格变成 Ġ）。
  • 然后按训练好的合并表，把常见字节对逐步合并成子词；GPT-2 的词表最终约 5 万个 token。

结果就是：常见词（如 "like"）往往是一个 token，不常见的词会被拆开。

Code Example 执行这个，亲眼看到文字怎么变成数字 
from mingpt.bpe import BPETokenizer
tokenizer = BPETokenizer()
text = "I like cats"
ids = tokenizer(text)
print("原始文字:", text)
print("变成的整数序列:", ids.tolist())
print("解码回去:", tokenizer.decode(ids[0]))
原始文字: I like cats 变成的整数序列: [[40, 588, 11875]] 解码回去: I like cats
发生了什么？
输入 "I like cats" 后，BPE 分词器把它变成了三个整数 [40, 588, 11875]。
这三个数字就是模型真正“看到”的内容。模型从来不直接处理字母，它只处理整数 ID。
最后一行把 ID 解码回文字，证明这个转换是可逆的。
建议自己动手： 把 text 改成其他句子（比如 "Hello world" 或中文），观察它会变成多少个 token。

4.2 第二步：把数字变成「有味道的向量」（Embedding）

现在我们有了一串数字： [40, 588, 11875]。

模型要把每个数字「翻译」成一个长度为 48（gpt-nano）或 768（gpt2）的向量。

你可以把这个向量想象成「这个词的身份证 + 性格描述」。

  • 数字 40（代表 I） → 一个 768 维的向量
  • 数字 588（代表 like） → 另一个向量

刚开始这些向量是随机乱写的（像刚出生的婴儿对所有词都没概念）。训练过程中，模型会慢慢调整这些向量，让意思相近的词的向量「长得像」。

重要：位置信息也要加进去！

如果只有词向量，模型会搞不清顺序。因为「我喜欢猫」和「猫喜欢我」词是一样的。

所以我们还要给每个位置加一个「我在第几个位置」的向量（Position Embedding），然后两个向量相加。

现在每个位置都有了一个「既知道自己是谁，又知道自己站在第几步」的向量。

最核心的形状变化（用小例子记住）：
输入：2 个句子，每句 3 个词 → 形状 (2, 3)
经过词嵌入 + 位置嵌入 → (2, 3, 48) ← 48 是 gpt-nano 的「脑容量」
经过所有 Transformer 层后依然是 (2, 3, 48)
最后输出 → (2, 3, 50257) ← 每个位置对「5万多个可能下一个词」的打分

5. 整体架构与数据流

GPT 是一个仅解码器（Decoder-Only）的 Transformer。给定 token 序列，预测每个位置的下一个 token 概率。

图：GPT 整体前向传播架构示意图

这个图展示了数据如何从输入 token IDs 一步步流经整个模型：

  • 最上方：输入 (B, T) 形状的 token ID 矩阵（B 是 batch 大小，T 是序列长度）。
  • 左右两侧：Token Embedding（把每个 token ID 映射成 n_embd 维向量）和 Position Embedding（为每个位置添加位置信息）。两者相加后得到初始表示。
  • 中间大框：n_layer 个 Transformer Block 堆叠。每个 Block 内部先做 Causal Self-Attention（因果自注意力，只能看左边和自己），再做 Feed-Forward MLP（前馈网络，维度先扩展 4 倍再缩回），中间用残差连接 + LayerNorm 稳定训练。
  • 下方：最终 LayerNorm + LM Head（线性层），把表示投射到 vocab_size 维的 logits（每个位置对下一个词的打分）。

与 BERT 的主要区别：BERT 是双向 Encoder，可以看到整个句子；GPT 是因果 Decoder，只能看到过去信息，这使得它特别适合自回归生成任务（如 ChatGPT 的续写）。与早期 RNN 相比，这里所有位置可以并行计算注意力，不再需要顺序递归。

数据流维度变化 —— 用最小的数字例子彻底理解

我们用一个超级小的例子帮助你彻底记住形状变化：

例子设定： 同时处理 2 个句子（batch=2），每个句子只有 4 个词（T=4），使用 gpt-nano（n_embd=48）

步骤形状直观理解
原始输入 token ID(2, 4)2 行 4 列的表格，每一行是一个句子的 4 个数字
词嵌入 (wte) 之后(2, 4, 48)每个数字都变成了一个长度 48 的向量，现在是三维的了
+ 位置嵌入(2, 4, 48)形状没变，只是内容加上了位置信息
经过 1 个 Block(2, 4, 48)形状永远不变！这很重要。Block 只是在“混合信息”，不改变大小
经过全部 3 个 Block(2, 4, 48)信息已经被混合了 3 次，越来越抽象
最后 lm_head 输出(2, 4, 50257)每个位置现在对 5 万多个可能的「下一个词」都打了一个分

核心记忆口诀：
「输入是 (批次, 长度)，中间永远保持 (批次, 长度, 脑容量)，最后一步才变成 (批次, 长度, 词表大小)」

用一句话把「文字 → 模型 → 下一个词」完整走一遍

我们用最短的例子：「I like」这两个词，让你看到数据在模型里是怎么流动的。

  1. 文字 → Token： "I like" → [40, 588] （两个整数）
  2. 变成向量：每个数字查表变成长度 48 的向量 → 形状 (1, 2, 48)
  3. 加上位置：第 0 个位置加「我在位置0」的向量，第 1 个位置加「我在位置1」的向量。
  4. 进入第一个 Block：
    • 先 LayerNorm 标准化一下
    • 做因果自注意力：位置 0 只能看自己，位置 1 可以看位置 0 和自己
    • 残差连接（把原来的信息加回来）
    • 再 LayerNorm + MLP（让每个位置自己多思考一下）
    • 又一次残差连接
  5. 同样流程再走 2 次（因为 nano 有 3 层）
  6. 最后输出：形状变成 (1, 2, 50257)。我们只关心最后一个位置（位置 1），对它做 softmax，就得到「下一个词最可能是哪个」的概率分布。
  7. 生成：从这个分布里挑一个词（可以挑概率最高的，也可以随机挑），把它变成 token ID 拼到序列后面，继续重复上面过程。

整个过程听起来很长，但代码其实只有 model.py 里 forward 函数的 20 行左右。

6. 自注意力机制：Transformer 的核心

自注意力（Self-Attention）是 Transformer 区别于之前所有序列模型的根本创新。它让模型能够直接"看到"序列中任意两个位置的关系，而不需要像 RNN 那样一步步传递信息。

第一性原理：为什么需要注意力？

想象你在读一句话："我去银行存钱，因为我需要支付房租。"当你读到"支付"时，你需要回想前面的"房租"和"银行"。大脑会自动把"支付"和"房租"关联起来，把"银行"和"存钱"关联起来。

RNN 只能把前面所有信息压缩成一个隐藏状态，容易丢失细节。注意力则允许每个词直接"查询"其他所有词，决定自己应该关注什么。

自注意力的计算过程（直觉 + 数学）

自注意力可以拆成三个概念：Query、Key、Value。可以这样理解：

  • Query (Q)：当前词"想问什么问题"？（"谁和我相关？"）
  • Key (K)：其他每个词"有什么信息"？（"我是第 3 个词，内容是 '存钱'"）
  • Value (V)：如果相关，其他词"要传递什么内容"？

计算分为五步：

  1. Q × K 点积：每个词和其他所有词做点积，得到一个"注意力分数"矩阵（T×T）。数值越大表示越相关。
  2. 缩放（Scale）：除以 sqrt(d_k)，防止维度高时点积太大把 softmax 推向极端。
  3. 因果掩码（Mask）：GPT 只能看左边的词，所以把未来位置设为 -inf（softmax 后变成 0）。
  4. Softmax：把每一行的分数归一化成概率分布。
  5. 加权求和：用概率分布对 Value 做加权平均，得到每个位置的输出。

用公式表达（单头注意力）：

Attention(Q, K, V) = softmax(QK^T / √d_k) · V

多头注意力机制

与其让一个注意力"专家"处理所有关系，不如让多个专家各司其职。每个头学习不同类型的注意力：一个头可能关注语法关系（哪个形容词修饰哪个名词），另一个头关注位置关系（"他"指代前文提到的谁），还有一个头关注语义相关性（"银行"和"存钱"的关联）。

计算时，Q、K、V 被分割成 n_head 份。每个头独立计算注意力，结果再拼接并通过一个线性投影合并。在 minGPT 的 gpt-nano 中：n_embd=48, n_head=3，每个头看到 16 维——这意味着每个头只在一个子空间里计算关系，但它们各自的贡献拼接起来后仍然恢复到完整的 48 维表达。

与线性注意力 / State Space Model 的对比

最近的工作（Mamba、RWKV、RetNet）探索了替代注意力的线性复杂度架构：

  • 线性注意力 / Mamba：用递归或状态空间模型替代 QK^T，将复杂度从 O(T²) 降到 O(T)。但代价是失去了"任意位置直接访问"的能力。
  • RWKV：结合了 Transformer 的训练便利性和 RNN 的推理效率。
  • RetNet：提出"保留机制"，在并行训练和递归推理之间优雅切换。

这些工作的共同主题：能否在保持 Transformer 质量的同时，消除 O(T²) 的扩展瓶颈？到目前为止，对于非常长的序列（>16K token），这些替代方案确实有优势；但对于大多数 LLM 应用（4K-8K 长度），标准注意力仍然是默认选择。

注意力作为"软性字典查找"

理解注意力的另一种方式是"软性字典查询"：

  • 你有一个键-值字典 {key_i: value_i}。
  • 当输入一个查询 q 时，你不只找一个精确匹配的键；你对所有键都计算"兼容性分数"。
  • 结果是从所有值中插值出来的——根据与每个键的匹配程度加权平均。

这就是为什么它被称为"软性"——它不是硬性选择某一个值，而是所有值的加权混合。softmax 的温度控制这个混合有多"尖锐"（是否接近 one-hot 选择）。

多头注意力的不同"专家"

多头注意力之所以有效，是因为不同的头可以学习到不同类型的注意力模式：

  • 有些头主要关注语法关系（主语-动词一致性、形容词-名词修饰）。
  • 有些头关注位置关系（相邻词、前一句的对应词）。
  • 有些头关注语义内容（"它"指代什么，"银行"在说什么语境）。
  • 有些头可能是冗余的（提供类似信息的多个视角，增加鲁棒性）。

因果掩码（Causal Mask）的重要性

在自回归语言模型中，因果掩码防止每个位置"偷看"未来的 token。这是 GPT 与 BERT 的核心区别之一：

  • 没有因果掩码：双向注意力（BERT）——每个位置看到整个序列，适合理解任务。
  • 有因果掩码：单向注意力（GPT）——每个位置只看到自己和之前的位置，适合生成任务。

在 minGPT 中，因果掩码通过一个下三角布尔矩阵实现。代码中直接创建并缓存它：

# causal mask to hide future tokens
self.register_buffer("bias", torch.tril(torch.ones(block_size, block_size))
                             .view(1, 1, block_size, block_size))

用具体的 3-token 例子跟踪注意力

假设序列是 "I like cats"（3 个 token）。token 0="I"，token 1="like"，token 2="cats"。

当我们为 token 1 计算输出时（它是第 2 个词 "like"）：

  • Step 1（生成 Q1）："like" 用一个投影矩阵乘以它的嵌入，生成查询向量 q1。
  • Step 2（准备 K、V）：所有三个 token 也都生成各自的键 k0、k1、k2 和值 v0、v1、v2。
  • Step 3（计算分数）：q1·k0（"like" vs "I"）= 0.7，q1·k1（"like" vs "like"）= 1.2，q1·k2（"like" vs "cats"）= -0.3。
  • Step 4（因果掩码 + Softmax）：分数 → [0.7, 1.2, -inf] → softmax → [0.38, 0.62, 0.0]。
  • Step 5（加权和）："like" 的输出 = 0.38×v0 + 0.62×v1。它完全忽略了 token 2（cats），因为因果掩码把它屏蔽了。

这就是每一个 token 在每一层如何"关注"左边所有 token 的过程。在多头注意力中，这个五步过程会在 n_head 个不同的 Q/K/V 子空间上并行发生（gpt-nano 中是 3 个头）。

核心代码实现（mingpt/model.py）

class CausalSelfAttention(nn.Module):
    def __init__(self, config):
        super().__init__()
        assert config.n_embd % config.n_head == 0
        # key, query, value projections for all heads
        self.c_attn = nn.Linear(config.n_embd, 3 * config.n_embd)
        # output projection
        self.c_proj = nn.Linear(config.n_embd, config.n_embd)
        # regularization
        self.attn_dropout = nn.Dropout(config.attn_pdrop)
        self.resid_dropout = nn.Dropout(config.resid_pdrop)
        # causal mask
        self.register_buffer("bias", torch.tril(
            torch.ones(config.block_size, config.block_size))
            .view(1, 1, config.block_size, config.block_size))

c_attn 是一个单独的线性层，一次性生成 Q、K、V（3 倍嵌入维度）。然后通过 .split 将它们拆开。然后进行批量矩阵乘法计算注意力分数。

minGPT 实现中的实践洞察

minGPT 的实现虽然简洁，但包含了所有核心要素：

  • 多头注意力在 gpt-nano 中：48 维嵌入被 3 个头分成 3×16 维。每个头只在一个 16 维子空间上计算注意力——但它们的输出拼接后恢复到完整的 48 维。
  • 因果掩码使用 masked_fill：将来位置设为 -inf，让 softmax 输出 0。这个操作虽然简单，但实际计算中仍然会为未来位置进行完整的 QK^T 计算——只是结果被忽略了。FlashAttention 等优化可以跳过这些计算。
  • 注意力 dropout 是在注意力权重上应用的（softmax 之后），而不是在分数上。这类似于在"软性选择"中随机丢弃一些连接。

7. Transformer Block 详解

Transformer Block 是 GPT 的基本构建单元。每个 Block 包含两个子层，每个子层周围都有残差连接和层归一化（LayerNorm）。

一个标准的 Transformer Block 遵循 Pre-LayerNorm 模式（GPT-2 引入）：

x ← x + Attention(LayerNorm(x)) x ← x + FFN(LayerNorm(x))

其中 Attention 可以是因果自注意力、交叉注意力或掩码注意力。在 GPT 的纯 decoder 架构中，所有 Block 都使用因果自注意力。

为什么 Transformer Block 要这样设计？

可以把一个 Block 类比为一场高效的会议：

  • LayerNorm（调节音量）：在每个人发言前，先把所有人的音量调到统一水平。LayerNorm 稳定了每个子层的输入分布，使训练更加稳健。
  • 注意力（讨论环节）：每个人查看其他人说的内容，决定自己要说什么。这是信息交换的环节。
  • 残差连接（保留笔记）：即使讨论跑偏了，你还有之前的笔记可以参考。这使得梯度可以直接流过整个网络，解决了深层网络的退化问题。
  • FFN（深入思考）：在获取了所有信息后，FFN 让每个位置独立地"深入思考"——将收集到的信息转换成更有用的表示。

FFN 的 4 倍扩展——为什么有效？

前馈网络通常将嵌入维度扩展到 4 倍：n_embd → 4×n_embd → n_embd。这样设计是因为它给模型提供了一个"暂存空间"来扩展中间表示。注意力负责收集信息（跨位置的混合），而 FFN 负责处理信息（每个位置的独立转换）。4× 倍率是实践中被证明效果良好的选择，现代架构如 LLaMA 和 Mistral 也继承了这一设计。

设计要点（简化版）

  • 为什么先 LayerNorm 再子层？ GPT-2 发现 Pre-LN 更稳定——梯度可以直接通过残差路径流动。Post-LN 在深层网络中容易导致训练不稳定。
  • 注意力 + FFN 的顺序重要吗？ 经验表明"先注意力再 FFN"比反过来要好。注意力负责混合信息，FFN 负责独立处理——先获取上下文再深入思考更合理。
  • Dropout：在注意力权重上和残差输出上应用 dropout 作为正则化。对于小模型，dropout 很有帮助（防止过拟合）；对于大模型和大量数据，dropout 通常被关闭或设得很小。

8. GPT 完整架构与设计选择

现在我们将所有组件组合成完整的 GPT 模型。从嵌入层到输出层，GPT 是一个纯 decoder-only 的 Transformer 架构。

GPT 完整数据流

  1. Token 嵌入：输入 token ID 通过 wte（词嵌入矩阵）映射为密集向量。形状：(B, T) → (B, T, n_embd)。
  2. 位置嵌入：通过 wpe（位置嵌入矩阵）为每个位置添加位置信息。形状：(T,) → (T, n_embd)。广播到批次维度。
  3. 逐 Block 处理：通过 n_layer 个 Transformer Block 依次处理。每个 Block 保持形状 (B, T, n_embd)。
  4. 最终 LayerNorm：在输出到 lm_head 之前做一次归一化。
  5. LM Head：将 (B, T, n_embd) 投影到 (B, T, vocab_size)，得到每个位置对词表中每个词的分数（logits）。
  6. （推理时）Softmax + 采样：logits → softmax → 概率分布 → 采样下一个 token。

架构对比：BERT、LLaMA、Mistral 等

为什么 Pre-LN 比 Post-LN 更稳定？

在 Post-LN 中，层归一化在残差相加之后：Output = LN(x + Sublayer(x))。这意味着归一化在残差混合之后进行，梯度的路径更长。在 Pre-LN 中：Output = x + Sublayer(LN(x))。归一化在子层之前，残差路径是完全不受干扰的——梯度可以直接流过整个网络。实验表明，Pre-LN 允许更高的学习率和更深层的网络而不爆炸。

架构演进：代码级深入解析

RMSNorm vs LayerNorm

RMSNorm 是 LayerNorm 的简化版本——它只对均方根进行归一化，而不减去均值。LLaMA 证明了这对 Transformer 训练同样有效，且节省了约 5-10% 的归一化计算量。

# LayerNorm: y = (x - E[x]) / sqrt(Var[x] + eps) * gamma + beta
# RMSNorm:  y = x / sqrt(mean(x^2) + eps) * gamma

SwiGLU vs GELU

SwiGLU 是 Swish + GLU（门控线性单元）的组合。相比 GELU，它在相同的计算预算下通常能获得更好的质量。代价是 FFN 的参数增加了约 33%（因为门控需要额外的投影矩阵）。

# GELU:            output = x * Phi(x)
# SwiGLU:          output = (x * sigmoid(x * beta)) * (W_gate * x)

从 MHA 到 GQA：KV Cache 的演进

多头注意力（MHA）中每个头都有自己的 K 和 V。对于长序列，KV cache 变得巨大，成为推理的瓶颈。GQA（分组查询注意力）让多个查询头共享键和值头，在几乎不损失质量的情况下大幅减少了 KV cache 大小。

前向传播

def forward(self, idx):
    B, T = idx.shape
    # token + position embeddings
    tok_emb = self.transformer.wte(idx)
    pos_emb = self.transformer.wpe(torch.arange(T, device=idx.device))
    x = tok_emb + pos_emb
    # forward through transformer blocks
    for block in self.transformer.h:
        x = block(x)
    # final layer norm
    x = self.transformer.ln_f(x)
    # language modeling head
    logits = self.lm_head(x)
    return logits

权重初始化

minGPT 使用 N(0, 0.02) 初始化所有权重。为什么是 0.02？因为 Transformer 的残差路径会导致方差累积。具体来说，GPT-2 对残差投影（注意力输出和 FFN 输出）使用了 N(0, 0.02/sqrt(2*n_layer)) 的缩放初始化，以抵消深层网络中残差方差累积的影响。这个细节对于小模型（minGPT 级别）影响不大，但在 48 层以上的模型中会显著影响训练稳定性。

优化器配置（configure_optimizers）

minGPT 将参数分为两组：decay（线性层权重，应用权重衰减）和 no_decay（偏置、LayerNorm 参数、嵌入权重）。这种分离是 GPT 训练的标准实践——对偏置和归一化参数应用正则化没有意义，因为它们的维度很低或作用不同。

加载预训练权重（from_pretrained）

minGPT 支持从 Hugging Face 加载 GPT-2 预训练权重。这需要在两个框架之间映射参数名称。虽然 minGPT 本身通常只用于从头训练，但这个功能让你可以加载一个完整的 GPT-2 并用 generate.ipynb 体验文本生成。

磁盘提醒：from_pretrained(model_type) 会把模型权重下载到 Hugging Face 缓存目录。学习生成流程时使用 gpt2 就够了；不要随手把 model_type 改成 gpt2-xl，它会下载数 GB 权重，并且加载时也需要大量内存/显存。

10. GELU — 高斯误差线性单元

GELU 是 GPT-2 选择的激活函数。它比 ReLU 更平滑，不会完全截断小的负值。

GELU(x) = x · Φ(x)
其中 Φ(x) 是标准正态分布的累积分布函数（CDF）

精确公式 vs 近似公式

精确 GELU 需要计算误差函数 erf，速度较慢。minGPT 使用 NewGELU，它采用 tanh 泰勒展开近似（与 Google BERT / OpenAI GPT 相同）：

GELU(x) ≈ 0.5x · ( 1 + tanh( √(2/π) · (x + 0.044715x³) ) )

11. Softmax 函数

Softmax 将任意实值向量转换为概率分布（所有值 ∈ (0,1)，总和为 1）。在 minGPT 中用于两个地方：

  1. 注意力：将 Q·Kᵀ 分数转换为注意力权重
  2. 文本生成：将最后一个位置的 logits 转换为下一个 token 的概率
softmax(zᵢ) = exp(zᵢ) / Σⱼ exp(zⱼ)

12. BPE 分词器（字节对编码）

BPE 将任意 UTF-8 文本编码为整数序列。它是 GPT-2 使用的分词方案，词汇表大小为 50,257。

图：BPE 分词流程

下图展示了从原始文本到最终 token ID 的四个主要步骤：

  1. 正则表达式预分词：按空格、标点、撇号等将句子分割为粗粒度片段。
  2. 字节映射（bytes→unicode）：将每个 UTF-8 字节映射到"可显示"的 Unicode 字符（空格变成 Ġ）。
  3. BPE 合并：应用训练好的合并规则，自底向上合并频繁出现的字节对为子词。
  4. 获得最终 token ID，输入 Transformer。

与 BERT 的 WordPiece 或 LLaMA 的 SentencePiece 相比，GPT-2 BPE 的标志性特点是将前导空格编码到 token 中（Ġ），使模型能更好地区分词边界。字节级方案（如 ByT5）完全跳过合并步骤，但会产生更长的序列。

编码流程

  1. 预分词：使用正则表达式将文本分割为单词片段（处理空格、标点等）
  2. 字节映射：将每个字节（0-255）映射到可打印的 Unicode 字符（避免不可见字符）
  3. BPE 合并：应用训练好的 merge ranks，迭代合并优先级最高的字节对
  4. 查找：在 encoder.json 词汇表中查找合并后的 token，获取整数 ID

BPETokenizer 封装

与 WordPiece、SentencePiece、Unigram 的对比

BPE 不是唯一的分词方法。不同模型家族选择了不同的方案：

  • WordPiece (BERT)：与 BPE 类似，但基于语言模型似然增益合并，而非纯频率。
  • SentencePiece (T5, LLaMA, Mistral)：直接在 Unicode 字符上操作，无需正则预分词。对多语言支持更自然。LLaMA 系列使用 SentencePiece + BPE 算法。
  • Unigram LM：从大量词汇开始，逐步移除对语言模型贡献最小的 token（概率论视角）。

这些方法在词汇表大小（通常 30k-128k）和罕见词处理上各有取舍。但核心思想相同：用有限数量的 token 覆盖自然语言的统计规律，同时保持可逆性。

分词器如何影响模型能力（第一性原理）

分词器是模型对世界的第一个"感知过滤器"：

  • 如果分词器将"人工 智能"拆成很多片段，模型需要更多层来学习这个概念。
  • 对缩进和括号敏感的代码分词器使代码任务更容易学习。
  • 多语言模型的分词器必须在各语言之间平衡 token 效率。

现代模型越来越重视分词器训练（更多数据、更好算法），因为它直接影响模型的"感知粒度"和最终性能上限。

13. 训练的本质：从损失函数到参数更新

在前面的章节中，我们从第一性原理理解了学习就是"预测 → 评分 → 调整"。本章将这一过程在 GPT 训练中的每个细节展开，并对比工业实践和其他优化方法。

深入理解损失函数

在语言建模中，我们几乎总是使用交叉熵损失（Cross Entropy Loss）。

从信息论的角度看，它衡量的是"模型预测的概率分布"与"真实的下一个词 one-hot 分布"之间的 KL 散度。

为什么不用 MSE（均方误差）？因为在分类任务中，MSE 对概率的惩罚不够"尖锐"。交叉熵在模型对正确答案信心不足时给出非常大的梯度，推动模型快速修正。

在代码中：

loss = F.cross_entropy(logits.view(-1, vocab_size), targets.view(-1), ignore_index=-1)

ignore_index=-1 是一个非常实用的技巧。在 adder 项目中，它从损失中屏蔽了"问题部分"（输入数字），让模型只从"答案部分"学习。

梯度下降与优化器

最简单的梯度下降：

θ ← θ - η · ∇L

其中 η 是学习率。

在实践中，我们使用 AdamW（GPT 的标准）：

  • 动量（Momentum）：使更新方向更稳定，在陡峭的损失表面上减少震荡。
  • 自适应学习率：对频繁更新的参数用小步，对稀有参数用大步。
  • 权重衰减（Weight Decay）：仅对权重矩阵应用 L2 正则化，不对偏置和 LayerNorm 参数应用（AdamW 与 Adam 的关键区别）。

在 minGPT 的 configure_optimizers 中，参数被明确分为两组：

  • decay 组：线性层权重
  • no_decay 组：偏置、LayerNorm、嵌入权重

优化器对比

优化器特点LLM 中的使用
SGD + Momentum简单，理论性质好大模型很少使用
Adam自适应 + 动量早期常用
AdamW正确的权重衰减实现当前 GPT 模型标准

梯度裁剪（Gradient Clipping）

在 Transformer 训练中，某些层很容易出现梯度爆炸。minGPT 使用 clip_grad_norm_(model.parameters(), 1.0)，将全局梯度范数裁剪到 1.0。这是稳定大模型训练最简单有效的技巧之一。

损失地形图：为什么学习率的选择至关重要

想象损失函数是一座连绵起伏的山脉。模型的参数就是放在这座山上的一个球，训练的过程就是让球沿着山坡向下滚，寻找最低的谷底。

上图展示了损失地形的一个剖面。三种场景：

  • 学习率太小（红色）：球几乎不动，卡在一个缓坡上。训练进度极慢，最终也无法到达谷底。实践中表现为 loss 下降极慢，最终停在一个较高的值。
  • 学习率合适（绿色）：球顺利滚入谷底。这就是调好学习率的表现——loss 稳步下降，最终到达一个不错的最小值。
  • 学习率太大（橙色）：球因为动量过大，直接弹出谷底。训练中表现为 loss 突然暴涨——这就是梯度裁剪要解决的问题：防止球在梯度异常大时跳出太远。

为什么需要 Warmup：在初始化时，模型参数是随机的，起点附近的损失地形极其陡峭且混乱。一大步走错就可能永久破坏训练稳定性。Warmup 让模型先用极小的步幅探路，找到方向后再全速下降。

学习率调度

现代 LLM 训练几乎总是使用 Warmup + Cosine Decay 或 WSD（Warmup-Stable-Decay）调度。

  • Warmup：在前几千步中，学习率从 0 线性增加到峰值，防止早期不稳定。
  • Cosine Decay：学习率平滑衰减到一个很小的值。
  • 稳定阶段：对于非常大的模型，有一个学习率保持不变的阶段。

深入理解 AdamW 超参数：betas=(0.9, 0.95)

AdamW 中的两个 beta 值控制着优化过程中完全不同的方面：

  • beta1=0.9（动量）：想象球滚下山坡。0.9 意味着"90% 保留之前的方向 + 10% 采纳新梯度"。beta1 越高（如 0.95），轨迹越平滑但转向越慢；越低（如 0.8），响应越快但来回抖动。0.9 是默认值，因为它平衡了平滑性和响应速度。
  • beta2=0.95（自适应学习率）：它控制 Adam 回顾多远来估计每个参数的"典型梯度大小"。这是一个梯度平方的指数移动平均。beta2=0.95 意味着大约考虑最近 20 步的梯度统计。越高（如 0.999）估计越稳定，但在梯度统计变化时适应慢；越低（如 0.9）适应快但噪声大。

直觉速查表：beta1 控制方向的记忆（往哪走），beta2 控制步长的记忆（每步走多大）。如果训练剧烈震荡，增加 beta1；如果 loss 过早停滞，减小 beta2。

为什么用 AdamW 而不是 Adam？ Adam 有一个 bug：权重衰减被应用在自适应学习率内部，导致梯度大的参数被正则化得更狠。AdamW 将权重衰减解耦，直接应用在权重上。这个小小的修正显著提升了泛化能力，尤其是对于大语言模型。

数据是训练的另一半（第一性原理）

许多人只关注模型架构和优化器，但数据质量往往比模型大小更重要。从第一性原理看，模型只是一个"函数近似器"——它能拟合什么完全取决于你给它看什么数据。

在 Scaling Laws 时代，我们学到：

  • 高质量、干净、多样化的数据让同样大小的模型表现更好（Chinchilla 论文的核心发现）。
  • 数据重复会损害性能，甚至导致"记忆化"而非"泛化"。
  • 数据混合比例（代码、网页、书籍、对话、数学）需要仔细调整。不同的比例会产生截然不同的能力画像。

具体例子：相同架构，不同数据

试试用完全相同的 gpt-nano 模型在两个不同数据集上训练：

  • 数据集 A：100MB 清洗后的维基百科。模型会学到良好的语法、事实知识和连贯的段落结构。但它不会写代码、做数学或对话。
  • 数据集 B：100MB GitHub Python 代码。同样的模型会学到缩进模式、函数调用语法和变量命名规范。但如果让它写文章，它会生成胡言乱语。
  • 数据集 C（混合）：50MB 维基百科 + 50MB GitHub。模型会"两者都懂一点，但不精通"——除非总数据量大到足以让模型同时学习两种分布。这就是为什么 Chinchilla 的发现至关重要：每个领域都需要足够的 token。

给 minGPT 实验者的实用建议：如果你的 minGPT 模型学不会，首先要检查的不是架构——而是你的数据。(x, y) 配对是否正确？词汇表是否覆盖了文本？数据是否足够多样？一个完美的 Transformer 配上糟糕的数据，只会生成完美的垃圾。

实验建议：用同一个 minGPT 模型分别训练莎士比亚、Python 代码和随机数。架构完全不变，但模型会学到完全不同的模式。这是内化"数据是训练的另一半"的最直接方式。

训练稳定性：小模型 vs 大模型

训练一个几百万参数的 minGPT 和一个 70B 的模型在工程上是完全不同的世界。

  • 小模型（minGPT 级别）几乎不用担心 loss 尖峰。随机初始化 + 正常 AdamW 就能工作。
  • 大模型需要一系列"黑魔法"技巧：精确的初始化缩放（GPT-2 的残差投影用 1/sqrt(2N)）、QKV 偏置设为 0、LayerNorm epsilon 调优、梯度裁剪到 1.0、loss 缩放、BF16 主权重保护、选择性权重衰减等。
  • 当 loss 尖峰发生时，你通常需要回滚到之前的检查点并调整超参数，甚至重新设计初始化。

minGPT 故意省略了这些"细节"，因为它的目标是教育。在小实验中看不到的陷阱，会在真实的大模型训练中让你吃尽苦头。

训练循环（与第一性原理的对应）

回忆我们的第一性原理——每一行代码对应一个步骤：

while True:
    x, y = next(batch)                    # 获取一个批次
    logits, loss = model(x, y)            # 1. 前向：预测 + 计算损失
    model.zero_grad(set_to_none=True)
    loss.backward()                       # 2. 反向：计算梯度
    clip_grad_norm_(params, max_norm)     # （可选）防止梯度爆炸
    optimizer.step()                      # 3. 更新：真正地转动旋钮
    trigger_callbacks('on_batch_end')     # 回调（日志/评估/保存）
    if iter_num >= max_iters: break

循环的每次执行都在略微调整模型参数以降低误差，基于当前批次计算。这是"训练"最本质的动作。

14. 自回归生成

model.generate() 实现了自回归生成：一次预测一个 token，追加到序列中，重复直到达到所需长度。

生成流程：

  1. prompt：初始输入序列。
  2. forward：模型前向传播，获取最后一个位置的 logits。
  3. logits/T：应用温度缩放（控制随机性）。
  4. sample：基于温度和 top-k 采样下一个 token（或贪心 argmax）。
  5. append：将新 token 拼接到序列，重复直到达到 max_new_tokens。

与 BERT（一次性双向理解）不同，GPT 的生成必须是严格自回归的，因此因果掩码不可或缺。生产级 Transformer 通常会维护 KV cache 来避免重复计算历史 token；minGPT 的教学实现更简单，不做 KV cache，而是在每一步重新前向计算当前上下文。

生成参数详解

do_sampleFalseFalse=贪心 (argmax)，True=概率采样

15. 微调：让预训练模型适配你的任务

到目前为止，你已经理解了 GPT 是如何从头开始训练的。但在实际中，几乎没有人会从头训练一个基础模型。相反，他们会拿一个已有的预训练模型，进行微调（Fine-Tuning）——在更小、更有针对性的数据集上继续训练，让模型适应特定任务或领域。

什么是微调？

微调就是拿一个已经"学会说话"的模型（在数十亿 token 上预训练过），教它"在你特定的场景下该说什么"。预训练模型已经学会了语法、世界知识、推理模式和通用语言理解。微调将这些知识塑造成特定的目标。

从第一性原理来看：预训练给了模型一个好的初始化——它已经在损失地形中位于一个对应"通用语言"的谷底。微调将这个模型从通用谷底移动到对应你领域的具体谷底。因为起点很好，你只需要很少的数据和计算量。

核心直觉：预训练 = 学会说任何语言。微调 = 学会说你特定的方言。模型不会"忘记"语言如何运作，只是调整了优先级。

图：微调不是从零学，而是从通用谷底移动到领域谷底（看图说话）

下图把微调放回损失地形里理解：从头训练要从随机高地一路走到“会说话”的谷底；微调则从已经很好的预训练点出发，只需要沿着小坡移动到你的任务区域。

看图说话：微调不是把模型“重新教一遍语言”。它保留预训练学到的大部分通用能力，只让参数朝你的任务分布移动。数据太少或学习率太大时，这个移动会过头，于是出现灾难性遗忘。

全参数微调（Full Fine-Tuning）

更新模型的所有参数。这提供了最大的灵活性——每一层都可以适应新领域。但成本很高：

  • 一个 7B 模型在 FP32 下仅参数就需要 ~56GB 显存（不含优化器状态）。
  • 使用 AdamW 优化器，还需要 ~112GB 用于优化器状态（每个参数 2 个动量和 2 个方差）。
  • 再加上激活值、梯度和批数据。一个 7B 模型轻松超过 200GB。

全参数微调还有灾难性遗忘的风险——如果在狭窄领域上过度训练，模型可能会丢失通用能力。

LoRA（低秩适配）

LoRA 是目前最流行的参数高效微调方法。它不更新完整的权重矩阵 W（可能是 4096×4096），而是添加一条小的"旁路"：

W' = W + BA，其中 B ∈ ℝ^{d×r}, A ∈ ℝ^{r×k}, r ≪ min(d,k)

原始的 W 被冻结（不计算梯度）。只有很小的矩阵 A 和 B 被训练。对于一个 4096×4096 层，rank=8 时 LoRA 只训练 65,536 个参数，而不是 16,777,216 个——减少了 256 倍。

训练时 W 冻结、A/B 更新。推理时可以把它们合并：W_merged = W + BA（零额外成本）。或者分开保存以便快速切换任务。

图：LoRA 的低秩旁路——冻结大矩阵，只训练小矩阵

这张图说明 LoRA 为什么省显存：主干权重 W 不动，梯度只流向低秩矩阵 A 和 B。你不是复制一个新模型，而是给旧模型加一个很小的“方向修正”。

LoRA 最佳实践：

  • 秩（Rank）：大多数任务用 8-64。更高秩 = 更大容量但收益递减。r=16 是个好的默认值。
  • 目标模块：对注意力投影矩阵（Q, K, V, O）应用 LoRA 效果最好。领域特定任务可加上 MLP 层。
  • Alpha 缩放：LoRA 更新按 alpha/r 缩放。alpha=16, r=8 时缩放 2 倍。一般从 alpha = 2×rank 开始。

QLoRA：LoRA + 量化

QLoRA 将效率推向更高——将冻结的基础模型量化到 4-bit（NF4 格式），同时将 LoRA 适配器保持在 FP16。这使得在单个 48GB GPU 上微调 65B 模型成为可能——之前即使是 7B 模型的全参数微调都做不到。

  • NF4（NormalFloat4）：一种针对正态分布权重优化的 4-bit 数据类型。比标准 INT4 更适合模型权重。
  • 双重量化：对量化常数本身也进行量化，进一步节约内存。
  • 分页优化器：当 GPU 内存满时使用 CPU 内存存储优化器状态，按需交换页面。

QLoRA 相比全精度 16-bit 微调只有 ~1% 的质量损失，但内存减少了 4-8 倍。这使 LLM 微调变得平民化——任何人只要有消费级 GPU 就能微调最先进的模型。

微调数据最佳实践

微调质量最重要的因素是你的数据。架构远远没那么重要：

  • 质量重于数量：1000 个精心挑选的例子胜过 100,000 个嘈杂的网络数据。每个例子都应展示你想要的确切行为。
  • 多样化覆盖：覆盖模型会遇到的所有边缘情况。如果模型会看到 10 种用户请求，确保每种都有好的示例。
  • 输入输出对齐：(x, y) 对必须完全一致。如果你在 (问题, 答案) 对上微调，确保所有例子的答案格式相同。
  • 混入通用数据：为防止灾难性遗忘，在领域数据中混入 5-20% 的通用指令数据（如 ShareGPT、OpenAssistant）。
什么时候不该微调：如果你的需求是"回答关于公司文档的问题"，RAG（检索+提示词）通常比微调更好。微调教模型的是如何回答，而不是知道什么。当你需要模型学习新的模式（格式、语气、推理风格）时用微调，而不是需要它知道新的事实时。

与 minGPT 的联系

你在 minGPT 中学到的训练循环直接适用于微调：

  • 同样的 model(x, y) → loss → loss.backward() → optimizer.step() 循环。
  • 同样的交叉熵损失，只是在不同的数据集上。
  • 同样的梯度裁剪、学习率调度和回调机制。
  • 关键区别：你从预训练权重开始（初始 loss 低得多），使用小得多的学习率（通常 1e-5 到 5e-5，而不是预训练的 3e-4）。

如果你能从头训练一个 minGPT 模型，你已经理解了微调 90% 的内容。剩下的只是基础设施——LoRA 封装、量化和数据格式化。

16. minGPT 实现细节

minGPT 有意保持最小化，但真实世界的生产代码必须处理许多额外问题。下面我们深入分析每一个简化：minGPT 中是什么样的，为什么工业界必须加上它，以及为什么 Karpathy 故意为了教学而省略它。

1. 没有 FlashAttention / memory efficient attention

这是什么？
标准注意力在计算 Q@K^T 时会显式生成一个 T×T 的分数矩阵（对于批次和头，大小为 B×nh×T×T）。在 T=4096 时这个矩阵已经很大了；在 T=32k 时直接爆炸。FlashAttention 使用分块计算、融合 softmax 到 SRAM 中，避免将完整注意力矩阵写入 HBM，实现了"IO 感知"的计算。

minGPT 中（model.py, CausalSelfAttention.forward）： 

q, k, v = self.c_attn(x).split(...)
    att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(...))
    att = att.masked_fill(self.bias[:,:,:T,:T] == 0, float('-inf'))
    att = F.softmax(att, dim=-1)
    y = att @ v
每一步都生成中间 T×T 张量。

生产版本： 序列长度轻松达到 32k~128k+，在相同批大小下内存减少 3-10 倍。在长上下文上训练 70B 模型变得可行。

为什么省略？ 一旦使用 Flash，你就再也看不到"注意力分数是如何计算的"——核心过程变成了一个黑盒 kernel。教学目标是让你清晰地看到 mask、scale、softmax、加权求和的过程。

2. 没有混合精度训练（BF16 + FP32 主权重）

minGPT 中： 整个模型默认是 FP32。没有 autocast、GradScaler 或主权重副本。

生产影响： 加速 1.5-3 倍，内存减半（BF16 使用 2 字节而不是 4 字节）。没有它，训练 10B+ 模型不仅太慢，而且 A100 tensor core 也被浪费了。

为什么省略？ 混合精度涉及 amp、GradScaler、all-reduce 精度策略——对于理解"下一个词预测 + 梯度下降"来说，纯粹是工程噪声。

3. 没有梯度检查点（Gradient Checkpointing）

minGPT 中： 没有。Trainer 直接调用 loss.backward()，PyTorch 保留所有激活值。

生产影响： 在不增加 GPU 的情况下使批大小或序列长度增加 2-4 倍。对于长上下文训练至关重要。

为什么省略？ 重计算使训练代码和调试变得复杂。对于理解"loss.backward() 做了什么"，它是一个干扰项。

4. 没有 ZeRO / FSDP 分布式策略

minGPT 中： 只有 model.to(device) 和一个优化器。没有"多 GPU"的概念。

生产影响： 没有这些，GPT-3 175B、LLaMA 70B 永远不会存在。

为什么省略？ 分布式代码极其复杂（通信拓扑、梯度桶、参数重排、容错）。教学目标是首先理解"单个 GPU 上的单个 Block 做了什么"。

5. 没有 RoPE（旋转位置编码）

minGPT 中： 使用简单的可学习位置嵌入（wpe），最大长度固定为 block_size。

生产影响： RoPE 允许外推（extrapolation）到更长的序列，并且相对位置编码比绝对位置更符合注意力的需要。所有现代模型（LLaMA、Mistral、Gemma）都使用 RoPE 或其变体。

为什么省略？ 可学习嵌入是最简单的位置编码方式——"添加一个位置向量"比 RoPE 的旋转矩阵更容易理解。

6. 没有 GQA（分组查询注意力）

minGPT 中： 标准多头注意力，每个头有自己的 K 和 V。

生产影响： GQA 在不牺牲质量的情况下显著减少了 KV 缓存（约 2-4 倍）。对于长序列生成和部署到边缘设备至关重要。

为什么省略？ MHA 更简单、更经典。理解了 MHA 之后，GQA 只是"多个 Q 共享 K/V"的一个小变化。

本节的核心教训：minGPT 不是生产的代码。它是教学代码。理解每个省略背后的"为什么"比知道如何添加它们更有价值——因为它揭示了 Transformer 的核心机制与工程优化之间的界限。

18. Scaling Laws 与涌现能力

2020 年，OpenAI 发表了开创性论文"Scaling Laws for Neural Language Models"。通过大量实验，它展示了一个令人惊讶的事实：

语言模型的性能可以用三个变量之间的幂律关系来预测：模型大小、数据集大小和计算预算。

Scaling Laws 的核心发现

在一定范围内：

  • 增加模型参数（N）、数据（D）或计算量（C）都会以可预测的幂律方式降低损失。
  • N 和 D 之间存在一个最优比例（大致按比例共同增长）。
  • 在固定计算预算下，最好在模型大小和数据之间均匀分配计算量，而不是只堆模型或只堆数据。

这直接指导了 GPT-3、Chinchilla、LLaMA 等模型的训练配置。

图 12.1：Scaling Laws — 损失随计算量可预测地下降

下图展示了经典的幂律关系：随着计算预算增加，模型损失沿一条平滑、可预测的曲线下降。Chinchilla 的关键发现是：在相同计算预算下，将资源在模型大小和数据之间最优分配，比过度分配给模型大小（如 GPT-3 的做法）能产生更低的损失。

涌现能力

当模型规模超过某个阈值时，全新的能力会突然出现——就像物理学中的"相变"：

  • 算术：在一些评测中，多位数加法、链式推理等能力会在更大模型上突然明显增强；这并不表示小模型完全不能学算术，而是泛化和少样本能力差很多。
  • 上下文学习（few-shot）：超过一定规模后，在提示中提供示例能显著提升性能。小模型从上下文示例中的收益微乎其微。
  • 指令遵循：遵循复杂指令的能力在约 10-100B 参数之间涌现。
  • 多语言能力：跨语言迁移只在超过一定规模后才变得有效。
  • 代码生成：从编写简单脚本到实现完整算法。

这些能力不是逐步提升的——它们突然出现。这就是为什么简单增加规模就能产生质的飞跃，甚至令构建这些模型的研究人员也感到惊讶。

关于涌现的争论：一些研究者认为"涌现"部分是不连续评估指标的产物（例如准确率从 0% 跳到 50% 看起来像相变，但底层能力可能在更细粒度的指标上持续提升）。无论如何，实际效果是真实的：足够大的模型能做更小的模型根本做不到的事情。

Chinchilla Scaling Laws：计算最优的革命

原始的 Kaplan Scaling Laws (2020) 认为，要最小化损失，最佳策略偏向于更快地扩展模型参数。这导致了像 GPT-3 (175B 参数, 300B token) 这样的模型：参数很大，但相对于后来的标准，训练 token 数偏少。

但 DeepMind 的 Chinchilla 论文 (2022) 更系统地重新审视了这个问题。他们训练了 400 个不同大小和数据量的模型，得出了一个截然不同的结论：

  • 参数和数据要一起扩展：不是“参数数等于 token 数”，而是在固定计算预算下，参数量 N 和训练 token 数 D 都要随预算增长。常见的 Chinchilla 经验解读是：训练 token 数应远多于参数量，约几十个 token 对应一个参数的量级。
  • 之前的模型训练不足：GPT-3 (175B, 300B token) 约为 1.7 tokens/parameter；Chinchilla (70B, 1.4T token) 约为 20 tokens/parameter。后者参数更少，但每个参数看过的数据更多。
  • 相同计算量 → 更好的模型：Chinchilla 使用了与 GPT-3 接近的 FLOPs，但实现了显著更低的困惑度，说明早期大模型常常“模型太大、数据太少”。

这一发现彻底改变了训练策略。后续许多模型不再只追求更大的参数量，而是更重视训练 token 数、数据质量和去重清洗；也就是说，宁愿让一个相对小的模型“看得更充分”，也不盲目堆参数。

Scaling 的天花板

Scaling Laws 只在特定范围内成立。持续扩展面临：

  • 高质量数据的边际成本上升：公开互联网文本会重复、污染或质量参差不齐，继续扩展需要更强的数据筛选、合成数据和反馈数据。
  • 计算成本线性增长但收益可能递减。
  • 对齐难度增加（更大的模型更容易产生有害输出）。

minGPT 告诉我们，即使在极小的规模下，Transformer + 下一个 token 预测也能学习简单的序列模式。未来很可能需要"Scaling + 更好的算法/数据/架构"，而非单纯的扩展。

19. 位置编码与长上下文技术

为什么 Transformer 需要位置编码？

自注意力是置换不变的（permutation invariant）。没有位置信息，"I like cats"和"cats like I"对模型来说是一样的。

原始 Transformer 使用正弦位置编码（固定）。GPT 使用可学习的位置嵌入。

从绝对位置到相对位置

  • RoPE（旋转位置嵌入）：LLaMA、PaLM 等模型中常用的方案。通过旋转将相对位置信息编码到 Q 和 K 的点积中。
  • ALiBi：向注意力分数添加基于线性距离的偏置，允许在比推理更短的序列上训练。
  • YaRN, LongRoPE：RoPE 的插值/外推技术，用于 128k+ 甚至 1M 上下文。

RoPE 深入解析：数学与代码

RoPE 通过在 2D 子空间中旋转来变换 query 和 key 向量。对于位置 p 和维度对 (2k, 2k+1)：

R(p) · q = [q₂ₖ·cos(pθₖ) − q₂ₖ₊₁·sin(pθₖ), q₂ₖ·sin(pθₖ) + q₂ₖ₊₁·cos(pθₖ)]
其中 θₖ = 10000^(−2k/d)

关键性质：对 Q 和 K 应用 RoPE 后，它们的点积只依赖于相对位置 (m − n)，而非绝对位置：

(R(m)·q) · (R(n)·k) = q · R(n−m) · k

这种相对位置编码比固定长度的可学习位置表更适合长上下文扩展；但真正稳定地外推到更长序列，通常还需要训练策略或 RoPE 插值/缩放技术配合。

图 13.1：RoPE 可视化——2D 子空间中的向量旋转

下图显示一个 2D 向量随位置增加如何旋转。每个位置 p 获得唯一的旋转角度，两个旋转后向量的点积只取决于它们的角度差（相对位置），而非绝对值。

以下是一个最小实现（真实工程里通常会缓存 cos/sin）：

def apply_rope(x):
    # x: (B, n_head, T, head_size), head_size 必须是偶数
    B, n_head, T, head_size = x.shape
    half = head_size // 2

    # 每两个维度组成一个 2D 平面，并使用不同旋转频率
    freqs = 10000.0 ** (-torch.arange(0, half, device=x.device) / half)
    pos = torch.arange(T, device=x.device)
    theta = pos[:, None] * freqs[None, :]  # (T, half)
    cos = theta.cos()[None, None, :, :]    # (1, 1, T, half)
    sin = theta.sin()[None, None, :, :]    # (1, 1, T, half)

    x_even = x[..., 0::2]
    x_odd = x[..., 1::2]
    out = torch.empty_like(x)
    out[..., 0::2] = x_even * cos - x_odd * sin
    out[..., 1::2] = x_even * sin + x_odd * cos
    return out

与 minGPT 的可学习 wpe（简单的 nn.Embedding 查找）不同，RoPE 被嵌入到注意力计算本身中。这使其更适合长上下文建模。结合 YaRN 或 LongRoPE 等插值/缩放方法，现代模型可以向 128k 甚至更长上下文扩展。

长上下文挑战与工程解决方案

即使有好的位置编码，超长上下文（128k+）仍然面临：

  • KV Cache 内存爆炸（每个 token 存储 K 和 V）。
  • 注意力稀疏性：模型实际上只关注少数关键 token。
  • 训练数据中长序列稀缺。

常见的工程方法：

  • FlashAttention-2/3：大幅降低内存带宽需求。
  • PagedAttention (vLLM)：像操作系统分页一样管理 KV Cache。
  • StreamingLLM / 滑动窗口 + attention sink：只保留最近的窗口 + 少数"注意力沉没"token。
  • Ring Attention：在多个设备之间以环形方式分布序列分块。

这些技术让长上下文部署更可行，但 128k、1M 级别上下文仍然高度依赖模型大小、显存、并行策略和推理框架，是一个"工程 + 算法"的混合问题。

20. Transformer 的局限性与现代演进

Transformer 的根本问题

尽管取得了巨大成功，Transformer 从第一性原理出发就存在固有限制：

  1. 平方复杂度：自注意力是 O(n²)，在 128k、1M 上下文时内存和计算爆炸。在 n=128k 时，单个注意力矩阵有 128k × 128k = 每个头 160 亿个条目。
  2. 脆弱的位置编码：尽管 RoPE、ALiBi 有所改进，位置理解仍是"学习来的"而非"内置的"——模型必须从模式中推断位置，而不是将其作为原始属性。
  3. 缺乏归纳偏置：既是优点（能学习任何东西）也是缺点（简单模式需要比 RNN 多得多的数据，而 RNN 用更少的样本就能学会）。
  4. 幻觉与事实性：训练目标是"预测最可能的下一个 token"，而非"正确"。这是所有幻觉的根本原因。
  5. KV cache 瓶颈：即使使用 GQA，一个 70B 模型在 128k 上下文的 KV cache 也是数百 GB——超出大多数 GPU 的承载能力。

Mamba / State Space Model：工作原理

Mamba (2023) 建立在状态空间模型（SSM）之上。它不比较每个 token 与所有其他 token，而是维护一个随时间演化的隐藏状态，类似于 RNN 但有一个关键区别：状态转换是输入相关的（选择性的），而非固定的。这种选择性就是 Mamba 的强大之处——模型可以根据当前输入选择记住什么和忘记什么。

具体来说，一个简化的 Mamba 层做的工作：

# Mamba 风格 SSM（高度简化）
h = torch.zeros(hidden_size)  # 状态：固定大小，不增长
for x_t in input_sequence:    # 顺序扫描
    A = compute_A(x_t)         # 输入相关的状态转换
    B = compute_B(x_t)         # 输入相关的投影
    h = A @ h + B @ x_t        # 状态更新（类似 RNN）
    y_t = C @ h                # 从状态输出
# 总内存：O(hidden_size)，而非 O(n²)

优势：无 KV cache，O(n) 内存，隐藏状态理论上可以捕获无限上下文。权衡：Mamba 缺乏注意力"全局查看"的能力——信息必须顺序流过状态，这使得需要长距离检索的任务（如"大海捞针"）更难。

在标准 NLP 基准上，同等大小的 Transformer 仍略优于 Mamba，但 Mamba 在长序列效率上占主导地位。差距随着每个新的 SSM 变体（Mamba-2, H3 等）而缩小。

混合架构：两全其美

一个快速增长的趋势是结合 Transformer 和 SSM 层。通常，每第 N 层是注意力层（用于全局检索），其余是 Mamba 层（用于高效序列处理）。例如：

  • Jamba (AI21 Labs)：交替的注意力 + Mamba 层，FFN 使用混合专家（MoE）。
  • Zamba：跨 Block 共享注意力层 + Mamba 层。
  • Samba：交错的 Mamba + 滑动窗口注意力。

这些混合架构旨在保持注意力"大海捞针"的检索能力，同时保持 SSM 大多数计算的 O(n) 效率。

什么没有改变

尽管有所有这些创新，当今绝大多数生产系统仍然基于 Transformer 解码器。核心思想——下一个词预测、注意力、残差连接、归一化——仍然是该领域的中心。即使是混合模型也在最关键层使用注意力。问题不是"注意力会被取代吗？"，而是"在不牺牲质量的前提下，有多少计算可以更高效地完成？"

21. 幻觉、对齐与未来方向

为什么 LLM 会产生幻觉？

幻觉不是一个 bug；它是训练目标的一个特性。模型被训练为产生最可能的下一个 token，而不是在事实上正确。从第一性原理看：

  • 模型没有内部的"真理数据库"——它只有统计模式。
  • 面对模糊或罕见的知识时，它默认选择"训练数据中最常见的模式"，而这可能是不准确的。
  • 自回归性质意味着错误会累积：一个错误的 token 可能导致完全虚构的叙事。

具体示例：一个错误 Token 如何级联成幻觉

试想一个问题："埃菲尔铁塔是什么时候建造的，设计师是谁？"

正确答案是："埃菲尔铁塔建于 1887 年至 1889 年，由古斯塔夫·埃菲尔设计。"

现在，假设模型生成的前几个 token 出错了：

正确路径：埃菲尔铁塔建于 1887 年至 1889 年，由古斯塔夫·埃菲尔设计。
↓
略微出错：埃菲尔铁塔建于 1867 年 ...
↑ 仅仅一个 token 错了（1867 而不是 1887）。现在模型必须从这个错误事实继续生成。
↓
级联开始："为 1867 年世界博览会而建..."
模型生成了一个听起来合理的"事实"：1867 年确实在巴黎有一场世界博览会。但这在事实上是错误的——埃菲尔铁塔与 1867 年博览会毫无关系。
↓
继续编造："...由让-查尔斯·阿尔方德设计，庆祝法兰西第二帝国..."
模型生成了越来越多具体的（但编造的）细节。每个 token 都锁定了错误的历史叙事。到此为止，已经不可能恢复了。

为什么会这样：模型没有内部的"真理数据库"。它只知道"给定了前面的 token，下一个 token 最可能是什么？"一旦选择了 1867（因为它与 1887 共享统计模式——都是 4 位数字，都频繁出现在巴黎历史语境中），模型就提交到了一个把 1867 当成事实的分支上，所有后续 token 都基于这个错误前提生成。这就是自回归错误积累——幻觉的核心机制。

为什么难以修复：模型的训练目标（下一个 token 预测）本身不提供任何"事实核查"机制。它需要一个外部知识库、检索增强生成（RAG）或独立的验证步骤——这些都不是核心自回归循环的一部分。这就是为什么幻觉被认为是一个开放的研究问题，而不是简单的 bug。

对齐：RLHF、DPO、Constitutional AI

对齐技术的目标是使模型输出与人类价值观和偏好匹配：

  • RLHF（基于人类反馈的强化学习）：在人类偏好上训练一个奖励模型，然后使用 PPO 微调 LLM 以最大化奖励。
  • DPO（直接偏好优化）：跳过奖励模型，直接从偏好对中进行优化。
  • Constitutional AI（宪法 AI）：使用一套原则（"宪法"）进行自我批评和修正输出。

图 15.1：RLHF 对齐流程

RLHF（基于人类反馈的强化学习）是一个三阶段过程，将模型输出与人类偏好对齐。奖励模型充当"人类偏好代理"——它学习人类更喜欢什么，PPO 训练基础模型以最大化这个奖励信号。

RAG（检索增强生成）

RAG 不是在模型参数中存储所有知识，而是在推理时从知识库中检索相关文档，并基于这些文档进行条件生成。这减少了幻觉，并使更新变得容易（只需更新知识库）。

减少幻觉的实用技术

除了上述高层方法，以下是具体、可直接操作的减少幻觉的技术：

1. 提示词策略

  • 思维链（CoT）：让模型在回答前逐步推理。这暴露了中间推理过程，减少了跳到错误结论的几率。示例："让我们一步步思考：首先，..."
  • 自我询问 / 验证：提示模型明确区分它知道的和不确定的。"只有在确信时才回答。如果不确定，说'我不知道'。"
  • 引用要求：要求模型为事实性声明引用来源。即使引用是编造的（一个已知问题），"假装引用"的行为迫使模型更加具体，这实际上降低了幻觉率。
  • 接地提示："仅基于以下上下文回答问题。如果上下文不包含答案，请说明。"这是 RAG 的基础。

2. 采样和解码策略

  • 较低的温度：temperature=0.1-0.3 使模型更加确定性，不太可能编造创造性的（但错误的）细节。Temperature > 1.0 会急剧增加幻觉。
  • Top-p（核）采样：p=0.9-0.95 将采样集中在最可能的 token 上，减少了选择不常见（幻觉）路径的机会。
  • 不采样（贪心解码）：使用 do_sample=False 或 argmax 给出最保守的输出。注意：minGPT 的 generate 会直接用 logits 除以 temperature，所以不要把 temperature 设成 0。
  • 对比解码：将目标模型的输出与一个较小的"业余"模型比较。业余模型也觉得可能的 token 被抑制，鼓励专家模型使用其更深的知识而不是表面模式。
  • 自洽性：生成多个答案（例如，5 个，temperature=0.3）并取多数投票。如果 5 个中有 4 个一致，答案可能是可靠的。如果它们不一致，你知道模型不确定。

3. 事后验证

  • 自我检查：生成答案后，问同一个模型："上面的回答在事实上正确吗？列出任何潜在的错误。"这利用了模型自身的知识来捕捉其错误——它有时比生成时"知道的更多"。
  • 外部事实核查：对于关于特定实体的声明，使用搜索引擎或知识库 API 在生成后验证每个事实性陈述。工具如 Google Fact Check Tools 或自定义检索可以捕捉错误。
  • 交叉模型验证：问两个不同的模型（如 Claude + GPT-4）同一个问题。如果它们一致，信心更高。如果它们不一致，进一步调查。
  • 不确定性估计：监控模型的 token 概率。如果第一个 token 的概率低（<0.5），或 logits 的熵高，说明模型"不确定"——将这些输出标记为需要人工审核。

4. 训练时技术

  • 幻觉数据的对比学习：构建成对数据，其中一个是事实性回答，另一个是同题的幻觉版本。通过偏好优化（DPO）训练模型偏好事实性回答。
  • 幻觉感知的数据增强：在微调数据集中，有意包含正确答案是"我不知道"或"没有这个信息"的例子。这教会模型承认无知是可以接受的。
  • 拒绝采样：在 RLHF/DPO 训练中，为每个提示生成多个回复，让人工评分者打分。只训练质量最高的回复。这自然减少了幻觉，因为幻觉回复得到低分并被排除在训练之外。

5. 架构方法

  • 内置检索：像 Retro（检索增强 Transformer）这样的模型将检索作为架构的一部分——每个 token 生成步骤都可以关注从数据库检索到的文档。这比预先添加上下文更紧密集成。
  • Tool-former 架构：模型被训练为在遇到事实不确定性时输出结构化工具调用（如 {search: "蒙古首都"}），而不是从记忆中生成。工具结果然后被反馈到上下文中。
  • 验证头：在模型上添加一个辅助分类头，预测"这个生成是否可能是事实性的？"可以用对比示例训练，并在推理时用于标记或拒绝不确定的输出。
总结：没有单一的"修复"幻觉的方法。最佳组合是：(1) 提示工程限制模型的生成空间，(2) 仔细选择的有利于保守输出的采样参数，(3) 事后验证捕捉错误，(4) 明确惩罚幻觉的训练技术。对于生产系统，RAG + 低温度 + 自我检查提供了最佳的可靠性-工作量比。

对齐的副作用与风险

对齐技术使模型更"有用"和"无害"，但也引入了新的挑战：

  • 过度拒绝：模型变得过于谨慎，拒绝无害的请求。
  • 对齐税：对齐会降低模型在某些基准测试上的原始能力（模型变得更"安全"但更"笨"）。
  • 奖励黑客：模型学会"取悦"奖励模型，而非真正理解人类意图。

这表明对齐本身是一个远未解决的开放研究问题。

现代 LLM 越来越多地被用作 agent，可以调用外部工具：计算器、代码解释器、搜索引擎、API。这将模型从"知道一切"转变为"知道如何查找"，大幅扩展能力的同时减少了幻觉。

未来方向

  • 测试时计算扩展（思维链、自洽性、思维树）。
  • 长文事实性和多跳推理。
  • 多模态理解（文本 + 图像 + 音频 + 视频）。
  • 具身 AI：将 LLM 连接到机器人控制。

评价的挑战

评估语言模型从根本上比评估传统 ML 模型更难。对于分类模型，你有明确的准确率指标。对于 LLM，"质量"是多维的：事实准确性、推理能力、创造力、指令遵循、安全性、语气等等。没有单一指标能捕捉所有这些方面。

Chatbot Arena：人类偏好排名

Chatbot Arena（由 LMSYS 运营）是目前最有影响力的 LLM 排行榜。它的工作方式与基准测试不同：

图：Chatbot Arena 的 Elo 更新过程

Arena 的核心不是“模型自己报分”，而是大量用户做盲测对比。每一场 A/B 投票都会轻微推动 Elo 分数，长期累积后形成相对排名。

  1. 盲测 A/B 对比：用户提交一个提示词。两个匿名模型生成回复。用户投票选择哪个更好（或宣布平局）。
  2. Elo 评分：受国际象棋排名启发。每个模型有一个 Elo 分数。当模型 A 击败模型 B 时，A 获得 Elo 积分，B 失去积分。积分变化取决于分差——击败一个弱得多的对手获得很少积分；击败一个强得多的对手获得很多积分。
  3. Bootstrap 置信区间：评分包含不确定性估计。一个 1250±15 的模型与 1200±10 的模型只有在置信区间不重叠时才显著不同。
  4. 风格 vs 质量控制：Arena 评分经过过滤，将"风格"偏好（格式、篇幅）与"质量"（准确性、有用性）分开。更啰嗦的模型通常得分更高，即使它们的事实准确性相似。
Elo_new = Elo_old + K × (S - E)

其中 K 是每场比赛的最大调整值，S 是实际结果（胜=1，平=0.5，负=0），E 是基于分差的预期得分。

自动评估：LLM-as-Judge

大规模运行人工评估成本高昂。一个常见的替代方案是使用强 LLM（如 GPT-4）作为自动裁判：

  • 成对比较："根据指令，哪个回复更好？A 还是 B？"裁判 LLM 直接比较 A 和 B。
  • 绝对评分："在 1-5 分范围内为这个回复的有用性评分。"裁判 LLM 给出数值分数。
  • 基于评分标准："检查回复是否满足以下 5 个标准中的每一个。"裁判遵循详细的评分标准。

LLM-as-Judge 的问题：位置偏差（偏好第一个或第二个回复）、冗长偏差（偏好更长的回复）、自我增强偏差（偏好自己的风格）和评分标准过拟合。尽管如此，LLM-as-Judge 与人类判断的相关性相当不错（Spearman 相关系数 0.5-0.7），被广泛用于快速迭代。

如何看待基准测试分数

阅读模型排行榜时，记住这些局限性：

  • 基准测试污染：如果模型训练数据包含了测试集，基准分数毫无意义。这是一个普遍问题——许多模型在训练时已经看过 MMLU 的例子。
  • 过拟合到基准测试：模型可以针对特定基准测试优化，而不提高通用能力。一个为 MMLU 优化的模型可能仍然无法完成基准测试之外的简单推理任务。
  • 饱和：顶级模型现在在 MMLU 上达到 >90%，在 HumanEval 上达到 >95%。这些基准测试不再能区分最佳模型。新的、更难的任务不断被需要。
  • 多维度评估：单一的"总体分数"隐藏了重要的权衡。一个编码基准得分高的模型可能在安全性方面得分很低。总是查看细分。
实用建议：为你的用例选择模型时，不要依赖单一的排行榜分数。用一小部分你自己的真实例子测试 2-3 个顶级模型。基准测试分数有助于筛选（这个模型是否在大致范围内？），但不适合最终选择（哪个模型最适合我的特定任务？）。

Elo 评分系统详解

由于 Elo 被 Chatbot Arena 和许多编码 agent 平台使用，理解其数学原理有助于解读评分：

  • 预期得分：E = 1 / (1 + 10^((R_B - R_A) / 400))。400 分的差距意味着强者的预期获胜频率是弱者的 ~10 倍。
  • K 因子：控制评分变化速度。高 K (32+) = 快速适应但噪音大。低 K (4-8) = 稳定但反映真实技能慢。Chatbot Arena 对成熟模型使用 K=4 以减少波动。
  • Elo ≠ 绝对质量：Elo 是相对的，不是绝对的。一个在 Arena 中有 1250 Elo 的模型可能比不上另一个评估池中 1100 Elo 的模型，因为 Elo 取决于对手池。

23. 深度思考、长期记忆与 Coding Agent 系统

从 minGPT 的"纯模型"到 Claude Code、Codex CLI 和现代 coding agent。

到现在为止，你已经理解了 GPT 模型：给定上下文，预测下一个 token。但像 Claude Code、Codex CLI 这样的工具似乎做的远不止"文本补全"：它们读取项目、运行命令、记住偏好、调用浏览器或文档服务、并遵循团队约定。这些能力中的大部分并非模型权重天生获得了 IDE 功能——它们来自模型能力 + 外部系统编排。

关键洞察：
深度思考主要依赖于模型在推理时分配更多计算量和更好的上下文组织。长期记忆、项目规则、工具调用、权限、文件 I/O 和自动化检查主要是产品/CLI/IDE 层的系统级能力。它们通常通过检索、文件、数据库、配置、工具协议、系统提示和上下文注入来实现——而不是每次重新训练模型权重。

现代 coding agent 不是单次模型调用——它是一个循环：构建上下文、调用模型、执行工具、观察结果、重复。模型权重处理推理和代码理解，而系统层管理上下文、工具、记忆和验证。

1. 什么是"深度思考"？

从用户的角度看，"深度思考"意味着模型在回答之前做了更多的中间推理：分解任务、比较方法、规划步骤、检查约束、验证结果。与普通答案的区别不仅仅是输入/输出格式，而是推理时计算预算、模型训练、工具编排和上下文管理的综合效果。

验证循环执行命令、观察结果、修订计划Agent 编排

因此，"深度思考"并非简单地通过提示词说"深入思考"就能实现。提示词可以促使模型更仔细地分解问题，但如果产品没有提供足够的推理预算、上下文、工具和验证循环，复杂任务仍然会停留在表面。

2. 长期记忆如何实现？

LLM 对话本质上仍然受限于上下文窗口。"长期记忆"通常不涉及将信息写入模型参数；它是一个外部记忆系统：

  1. 提取：从历史对话、用户修正、项目文件和执行结果中提炼稳定信息。
  2. 存储：写入本地文件、数据库、向量存储、配置文件或云用户画像。
  3. 检索：在新任务中，基于项目、路径、关键词、嵌入相似度或规则选择相关记忆。
  4. 注入上下文：将检索到的记忆放入系统/开发者/工具上下文中供模型使用。
  5. 更新与清理：过时、冲突或错误的记忆需要被覆写、合并或删除。

这与 minGPT 训练完全不同。minGPT 通过反向传播更新权重；coding agent 的长期记忆通常通过外部状态在会话之间保持。模型"看起来记得"，是因为系统检索了相关记忆并在下次启动时将它们放回上下文。

3. Claude Code 的记忆与规则层

Claude Code 的文档将项目记忆分为两种类型：用户编写的持久指令文件（例如 CLAUDE.md），以及工具基于修正、偏好和项目发现自动写入的记忆。两者都在新会话中作为上下文加载——但它们仍然不是模型权重的一部分。

这是一个关键点：CLAUDE.md 更像是一个"项目手册 + 团队规则"；自动记忆更像是"上次在这个仓库里踩过的坑"。要强制防止危险操作，你应该依赖 hooks、权限和工具策略，而非仅仅一条自然语言规则。

5. 上下文 vs 系统提示：有什么区别？

上下文是模型在单次调用中能看到的所有输入材料。它就像"给模型的全部考试材料和参考资料"，可能包括系统提示、开发者指令、用户问题、对话历史、项目文件片段、检索结果、长期记忆、工具输出、错误日志、截图描述等。

系统提示（system instructions）是上下文的一个特殊部分，通常放在最高优先级的位置，用于定义模型的身份、边界、风格、安全规则、工具使用原则和回答格式。它不是整个上下文——它是上下文中作为"主规则"的层级。

概念一句话解释示例
上下文此轮模型可读的所有内容系统提示 + 用户问题 + AGENTS.md + 记忆 + 文件内容 + 命令输出
系统提示上下文中最高优先级的行为规则"你是一个编码 agent；不要泄露秘密；修改前先读取文件；按特定格式回答"
用户提示用户希望模型完成的任务"修复这个 bug" "解释长期记忆如何工作"
检索/记忆内容由外部系统检索并注入上下文的事实材料项目偏好、历史摘要、文档片段、API 规范
工具输出模型调用工具时获得的新证据测试失败日志、文件内容、网页搜索结果

所以更准确的说法是：长期记忆通常由 CLI / App / IDE 层存储和检索，然后作为上下文的一部分注入模型；系统提示告诉模型这些记忆应该如何被理解、使用、遵守，或由更高优先级的规则覆盖。

在这个例子中，只有第一个块是"系统提示"。整个包一起构成了"上下文"。长期记忆不是系统提示本身——它由 CLI/App 检索并放入上下文中；系统提示规定了模型应如何使用这些信息。

回到第一性原理

我们在 minGPT 中学到的所有内容——下一个 token 预测、注意力、训练动态——都与理解 coding agent 的工作方式直接相关。Agent 的"推理"只是在精心构建的上下文条件下 LLM 生成 token。Agent 的"工具调用"只是模型输出的特殊 token，系统将其解释为命令。

理解 GPT 的基础知识给你在构建、调试和改进 agent 系统方面带来了巨大的优势。minGPT 训练循环中的"预测 → 评分 → 调整"循环在 agent 层级上被镜像为"行动 → 观察 → 重新规划"。

6. 如何比较现代 Coding Agent

coding agent 工具变化很快，GitHub stars、排行榜、许可证、模型支持范围都会频繁变化。因此本书不把这些信息写成固定排名，而是给出一个更稳定的比较框架。评估 Claude Code、Codex CLI、Gemini CLI、OpenCode、Cursor、Windsurf、Continue.dev 等工具时，重点看下面这些维度。

关键维度

  • 模型来源：是否绑定单一供应商，还是允许接入 OpenAI、Anthropic、Google、本地模型或 OpenRouter 等多种后端。
  • 项目规则：是否支持类似 AGENTS.md、CLAUDE.md、workspace settings 这样的项目级指令文件。
  • 工具权限：是否有沙箱、审批、只读模式、命令 allowlist/denylist，以及执行前后 hooks。
  • 上下文管理：是否能可靠读取项目结构、选择相关文件、保留任务历史，并避免把无关内容塞满上下文窗口。
  • 记忆机制：是否有跨会话记忆；记忆是文件、数据库、向量检索，还是只是当前会话摘要。
  • 验证闭环：是否擅长运行测试、解释失败、修改后复验，而不是只生成补丁文本。
  • 集成形态：终端、IDE、Web、云端 agent、移动/消息入口对应的工作流差异很大。

如何选型？

如果你最关心...优先考察
代码修改质量模型能力、上下文选择、测试/复验闭环、补丁是否小而准
安全沙箱、审批、命令限制、文件访问边界、hooks
团队规范项目规则文件、共享配置、可审计日志、CI 集成

建议：不要根据单一排行榜或 star 数选择 agent。最可靠的方法是拿你自己的真实仓库，准备 5-10 个常见任务：修 bug、加测试、改文档、跑失败用例、处理重构冲突。比较工具是否能正确读代码、提出小改动、运行验证并解释结果。

所有这些系统都建立在你在 minGPT 中学到的相同基础之上——下一个 token 预测、上下文管理和工具编排。模型权重只是一个组件；围绕它们的系统决定了现实世界的能力。

经典项目解析

projects/adder：教 GPT 做加法

这是 minGPT 中最具启发性的例子。它展示了如何从头开始训练 GPT 完成一个算法任务。

数据集设计洞察：答案以逆序编码（最低有效位在前）。这使自回归预测顺序与加法的自然计算顺序（从右到左的进位传播）对齐，大幅降低了学习难度。

损失仅在答案部分计算（使用 ignore_index=-1），迫使模型学习算法而不是死记硬背。

projects/chargpt：字符级语言模型

在字符级别上对任何文本文件训练 GPT。这是观察语言模型工作的最简单方式：

  • 词汇表：文本中所有唯一字符（比 BPE 小得多）。
  • 训练：下一个字符预测。
  • 生成：逐字符采样。

尽管简单，chargpt 展现了大语言模型的所有核心模式：上下文学习、连贯生成（到一定程度）以及捕捉文本风格和结构的能力。

实验 2：前向传播 + 形状追踪（最重要的运行）

代码示例 创建随机输入，运行前向传播，打印形状 
x = torch.randint(0, config.vocab_size, (2, 16)).to(device)
print("输入形状:", x.shape)          # (2, 16)
with torch.no_grad():
    output = model(x)
    logits = output[0] if isinstance(output, tuple) else output
print("Logits 形状:", logits.shape)  # (2, 16, 50257)
输入形状: torch.Size([2, 16]) ✓ 前向传播完成！ Logits 形状: torch.Size([2, 16, 50257])
关键观察：
我们创建了 2 个句子，每个 16 个 token。
经过前向传播后，logits 形状是 (2, 16, 50257)。
这意味着：对于每个句子的最后一个位置，模型对全部 50,257 个可能的下一词进行评分。
分数越高 = 模型认为这个词越可能出现在这里。
记住：在整个中间层中，形状保持 (batch, seq_len, n_embd)。只有最后的 lm_head 步骤将其转换为 (batch, seq_len, vocab_size)。

实验 3：使用前向钩子窥视模型内部

代码示例 注册前向钩子，查看嵌入层 / 第一个和最后一个 Block / lm_head 的统计信息 
activations = {}
def make_hook(name):
    def hook(m, inp, out):
        t = out[0] if isinstance(out, tuple) else out
        activations[name] = t.detach().cpu()
    return hook

hooks = []
hooks.append(model.transformer.wte.register_forward_hook(make_hook('embedding')))
hooks.append(model.transformer.h[0].register_forward_hook(make_hook('first_block')))
hooks.append(model.transformer.h[-1].register_forward_hook(make_hook('last_block')))
hooks.append(model.lm_head.register_forward_hook(make_hook('lm_head')))

_ = model(torch.randint(0, 50257, (1, 8)).to(device))
for n, a in activations.items():
    print(n, a.shape, '均值/标准差', a.mean().item(), a.std().item())
for h in hooks: h.remove()

实验 4：在最小数据集上使用 Trainer 训练（排序/计数模式）

下面演示如何子类化 Dataset 并将其交给 Trainer（灵感来自 demo.ipynb 的 SortDataset 和 learning_guide.ipynb 的简单模式）。

代码示例 最小数据集 + Trainer 训练 50 步 
from torch.utils.data import Dataset
class SimplePatternDataset(Dataset):
    def __init__(self, n=100, seq_len=8):
        self.n, self.seq_len = n, seq_len
    def __len__(self): return self.n
    def __getitem__(self, i):
        x = torch.arange(self.seq_len) % 5
        y = (x + 1) % 5
        return x, y

train_dataset = SimplePatternDataset(100, 8)
model_config = GPT.get_default_config()
model_config.model_type = 'gpt-nano'
model_config.vocab_size = 5
model_config.block_size = 8
model_small = GPT(model_config)
model_small.to(device)

trainer_cfg = Trainer.get_default_config()
trainer_cfg.max_iters = 50
trainer_cfg.batch_size = 8
trainer_cfg.learning_rate = 6e-4
trainer_cfg.num_workers = 0
trainer = Trainer(trainer_cfg, model_small, train_dataset)
trainer.run()

# 训练后生成
context = torch.tensor([[0]]).to(device)
print("从 [0] 生成的序列:", model_small.generate(context, 8, do_sample=False)[0].tolist())

关键观察：
模式是：0→1, 1→2, 2→3, 3→4, 4→0。模型仅用 50 步就学会了"计数"！
这证明下一个 token 预测目标即使使用极小的模型也能轻松捕获模算术。
